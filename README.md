# منصة حجز أتوبيس رحلة سيدي إبراهيم الدسوقي 🚌

نظام حجز مقاعد برابط واحد يفتحه الركاب من الهاتف أو الكمبيوتر، مع لوحة تحكم محمية للمسؤول.

**الرحلة الحالية (من `seed.sql`):**
- الأربعاء 28 أكتوبر 2026 — التحرك 7:30 صباحًا من الشروق
- يغلق الحجز الأحد 25 أكتوبر 2026 الساعة 11:59 مساءً بتوقيت القاهرة
- سعر التذكرة 300 جنيه للمقعد — الدفع على إنستاباي 01065553930
- نقاط التجمع: المستقبل، الشروق
- التجمع 7:00 صباحًا والانطلاق من الشروق 7:30 صباحًا — الحجز للرجال فقط — مسؤول الباص: محمد عبد الله ربيع
- المسار: الشروق ← الطريق الإقليمي ← سيدي أحمد البدوي ← سيدي عبد العزيز أبو المجد ← سيدي إبراهيم الدسوقي ← دار الدسوقية المحمدية بالرحمانية، مع خريطة وزر فتح المسار في خرائط جوجل
- السعة 50 مقعدًا

### الدفع وألوان المقاعد
1. الراكب يحجز فيظهر له المبلغ المطلوب (عدد المقاعد × 300) ورقم إنستاباي مع زر نسخ، ويُطلب منه كتابة رقم الحجز في ملاحظة التحويل.
2. مقاعده تظهر في مخطط الأتوبيس **بالأخضر الفاتح** (محجوز بانتظار الدفع).
3. بعد استلام التحويل، يضغط المسؤول «تأكيد الدفع» بجانب الحجز في لوحة التحكم، فتتحول المقاعد **للأخضر الغامق** فورًا عند كل الزوار.
4. الزائر لا يستطيع تعليم حجزه كمدفوع؛ قاعدة البيانات ترفض ذلك. كل تأكيد أو إلغاء دفع يُسجَّل في سجل العمليات مع اسم المسؤول ووقته.
5. التقارير وملف Excel يعرضان المبلغ المتوقع والمحصل والمتبقي، وحالة الدفع لكل راكب.

## 1. البنية التقنية

| الطبقة | التقنية | السبب |
|---|---|---|
| الواجهة | React 19 + TypeScript + Vite | سريعة وخفيفة على الهواتف |
| التصميم | Tailwind CSS v4، خط Cairo، اتجاه RTL | عربية بالكامل ومتجاوبة |
| الخادم وقاعدة البيانات | Supabase (PostgreSQL) | قاعدة مركزية مشتركة + صلاحيات على مستوى الصفوف |
| المصادقة | Supabase Auth (بريد + كلمة مرور) | للمسؤول فقط؛ الزائر لا يحتاج حسابًا |
| التحديث المباشر | Supabase Realtime + تحديث احتياطي كل 30 ثانية | تظهر الحجوزات فورًا على كل الأجهزة |
| التصدير | ملف XLSX يُنشأ في المتصفح (JSZip) | ورقة من اليمين لليسار ونص عربي سليم |
| النشر | Vercel (أو Netlify / Cloudflare Pages) | موقع ثابت بدون خادم خاص |

### كيف تُحمى السعة (أهم نقطة)

حساب المقاعد يتم **داخل قاعدة البيانات فقط**، وليس في المتصفح:

1. الزائر لا يملك صلاحية `INSERT` على جدول الحجوزات. يحجز فقط عبر الدالة `create_booking`.
2. كل عملية حجز أو تعديل أو إلغاء **تقفل صف الرحلة** (`SELECT … FOR UPDATE`)، فتُنفَّذ الحجوزات المتزامنة واحدة تلو الأخرى.
3. قادح (trigger) يعيد حساب `booked_seats` بعد كل تغيير، وقيد `CHECK (booked_seats BETWEEN 0 AND capacity)` يرفض أي حالة تتجاوز السعة حتى لو حاول أحد تجاوز الدالة.
4. منع الحجز المكرر: كل محاولة إرسال تحمل معرفًا فريدًا (`client_request_id`) عليه قيد `UNIQUE`؛ الضغط المزدوج أو إعادة الإرسال بعد انقطاع الشبكة يرجع نفس الحجز.

تم اختبار ذلك فعليًا: **150 طلب حجز متزامن** على رحلة سعتها 50 → امتلأت عند 50 بالضبط، و**40 طلبًا متزامنًا على آخر مقعد** → نجح طلب واحد فقط.

### الخصوصية والصلاحيات

| | الزائر | المسؤول |
|---|---|---|
| الحجز في رحلة مفتوحة | ✅ | ✅ (حتى بعد إغلاق الفترة، دون تجاوز السعة) |
| رؤية الإحصائيات | ✅ مجمّعة فقط | ✅ |
| قائمة الركاب | الاسم مختصر («أحمد م.»)، المقاعد، نقطة التجمع | كاملة مع الهواتف والملاحظات |
| أرقام الهواتف | ❌ لا تصل للمتصفح أصلًا | ✅ |
| الاستعلام عن حجزه برقم الحجز | ✅ | ✅ |
| تعديل/إلغاء الحجوزات، الرحلات، نقاط التجمع | ❌ (مرفوض في قاعدة البيانات) | ✅ |
| سجل العمليات | ❌ | ✅ (يُكتب تلقائيًا بقوادح ولا يمكن تعديله) |

الحماية مطبقة على الخادم بثلاث طبقات: صلاحيات الجداول (`GRANT`)، وسياسات Row Level Security، وفحص `is_admin()` داخل كل دالة إدارية. واجهة المستخدم تستخدم المفتاح العام فقط (anon key)، ولا يوجد أي مفتاح سري في الكود.

## 2. هيكل المشروع

```
supabase/
  migrations/20261014000000_init.sql   ← الجداول، القوادح، الدوال، RLS، الصلاحيات، Realtime
  seed.sql                             ← نقاط تجمع تجريبية + رحلة الجمعة القادمة
  tests/
    00_supabase_stub.sql               ← محاكاة بيئة Supabase للاختبار المحلي فقط
    10_acceptance_tests.sql            ← 80 اختبار قبول (منها اختبارات الدفع)
    20_concurrency_test.sh             ← اختبار الحجوزات المتزامنة
    run-db-tests.sh
src/
  lib/
    api/supabase.ts    ← الاتصال الفعلي بـ Supabase
    api/demo.ts        ← وضع معاينة تجريبي (بيانات في المتصفح فقط)
    validation.ts      ← التحقق من الرقم المصري والنموذج
    xlsx.ts, report.ts ← تصدير Excel والتقارير
    *.test.ts          ← اختبارات الوحدة
  components/          ← النموذج، مخطط الأتوبيس، القائمة العامة، عناصر الواجهة
  pages/PublicPage.tsx ← صفحة الحجز العامة
  pages/admin/         ← لوحة التحكم: الحجوزات، الرحلات، نقاط التجمع، التقارير، سجل العمليات
```

### الجداول

- `trips` — الرحلات: التاريخ، موعد التحرك، نقطة الانطلاق، الوجهة، السعة (≤ 50)، سعر المقعد، رقم إنستاباي، فتح/إغلاق الحجز، الحالة (مفتوحة / مكتملة / مغلقة / ملغاة).
- `pickup_points` — نقاط التجمع. لا تُحذف؛ تُوقف فقط، فتبقى في الحجوزات القديمة.
- `trip_pickup_points` — النقاط المعتمدة لكل رحلة.
- `bookings` — الحجوزات (معرف UUID + رقم حجز `DSQ-XXXX-XXXX`، حالة الدفع ووقته، وقت الإنشاء والتعديل والإلغاء). الإلغاء ناعم ولا يُحذف أي حجز.
- `admin_users` — المستخدمون الإداريون (مرتبطون بـ Supabase Auth).
- `audit_log` — سجل العمليات.

## 3. التشغيل والنشر خطوة بخطوة

### أ. إنشاء قاعدة البيانات على Supabase (مجاني)

1. أنشئ حسابًا على [supabase.com](https://supabase.com) ثم **New project**. اختر منطقة قريبة (مثل Frankfurt).
2. افتح **SQL Editor** → **New query**، الصق محتوى `supabase/migrations/20261014000000_init.sql` كاملًا، واضغط **Run**.
3. شغّل `supabase/seed.sql` بنفس الطريقة لإضافة نقاط التجمع الأربع ورحلة 28 أكتوبر بسعرها ورقم إنستاباي.
4. أنشئ حساب المسؤول: **Authentication → Users → Add user → Create new user** (بريد + كلمة مرور قوية، وفعّل Auto Confirm).
5. امنحه صلاحية المسؤول من SQL Editor:
   ```sql
   insert into public.admin_users (user_id, display_name)
   select id, 'مسؤول الرحلة' from auth.users where email = 'admin@example.com';
   ```
6. أوقف التسجيل العام: **Authentication → Sign In / Providers → Allow new users to sign up = Off** (لا يحتاج الزوار حسابات).
7. تأكد أن Realtime مفعّل: **Database → Publications → supabase_realtime** يجب أن يضم `trips` و `bookings` و `pickup_points` (ملف الـ migration يضيفها تلقائيًا).
8. انسخ من **Project Settings → API**: قيمة `Project URL` وقيمة `anon public` key.

### ب. التشغيل محليًا

```bash
npm install
cp .env.example .env.local     # ثم ضع القيم من الخطوة 8
npm run dev                    # http://localhost:5173
```

بدون ملف `.env.local` يعمل التطبيق في **وضع المعاينة التجريبي** مع شريط تحذير أصفر واضح: البيانات تُحفظ في المتصفح فقط ولا تُشارك بين الأجهزة (للتجربة فقط). دخول المسؤول التجريبي: `admin@demo.local` / `demo1234`.

### ج. النشر على Vercel

1. ارفع المجلد على GitHub (مستودع خاص أو عام).
2. على [vercel.com](https://vercel.com): **Add New → Project** واختر المستودع. سيتعرف على Vite تلقائيًا.
3. في **Environment Variables** أضف:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. اضغط **Deploy**. الرابط الناتج (مثل `https://dasuki-bus.vercel.app`) هو رابط الحجز الذي تشاركه.
5. في Supabase: **Authentication → URL Configuration → Site URL** ضع رابط Vercel.

- رابط الحجز العام: `https://your-site.vercel.app/`
- لوحة التحكم: `https://your-site.vercel.app/#/admin`

> مفتاح `service_role` لا يُستخدم ولا يجب وضعه في أي مكان في هذا المشروع.

## 4. الاستخدام (للمسؤول)

1. رحلة 28 أكتوبر جاهزة من `seed.sql`. لتعديل الموعد أو السعر أو رقم إنستاباي: **الرحلات ← تعديل**. ولرحلة أخرى مستقبلًا: **إنشاء رحلة جديدة** (لا تُنشأ أي رحلة تلقائيًا).
2. شارك رابط الحجز في مجموعة الواتساب.
3. تابع **الحجوزات**: بحث بالاسم أو الهاتف أو رقم الحجز، تصفية بنقطة التجمع والحالة وحالة الدفع، ترتيب، **تأكيد الدفع**، تعديل، إلغاء، استعادة، أو إضافة حجز يدوي.
   - إذا أُلغي حجز مدفوع تظهر عليه علامة «مدفوع — راجع الاسترداد» لتتذكر رد المبلغ.
4. الرحلة تصبح «مكتملة» تلقائيًا عند 50 مقعدًا، وتعود «مفتوحة» إذا أُلغي حجز. يمكن إغلاق الحجز يدويًا في أي وقت، وتُغلق تلقائيًا عند موعد الإغلاق.
5. قبل السفر: **تصدير Excel** (قائمة الركاب، ملخص الرحلة، حسب نقطة التجمع، الحجوزات الملغاة) أو **طباعة القائمة** (A4 أفقي مع عمود «حضر» للتحضير).
6. الرحلات السابقة تبقى بحجوزاتها في قائمة اختيار الرحلة، والتقارير متاحة لها.

## 5. الاختبارات

```bash
npm test          # اختبارات الوحدة: التحقق، الرقم المصري، التوقيت، ملف Excel (14 اختبارًا)
npm run test:db   # اختبارات قاعدة البيانات على PostgreSQL محلي (ليس على مشروع Supabase الحقيقي)
```

`test:db` يحتاج PostgreSQL 15+ محليًا، مثلًا:
```bash
PGHOST=localhost PGPORT=5432 PGUSER=postgres npm run test:db
```
ينشئ قاعدة مؤقتة `dasuki_test` ويحذفها في البداية.

### نتائج آخر تشغيل (PostgreSQL 16)

- ✅ 80 اختبار قبول في قاعدة البيانات (منها 15 للدفع والسعر ورقم إنستاباي)
- ✅ 3 سيناريوهات تزامن (150 / 40 / 30 عميلًا متزامنًا)
- ✅ 14 اختبار وحدة
- ✅ اختبار الواجهة في Chromium (هاتف 390px وكمبيوتر 1366px): حجز، ضغط مزدوج، تجاوز السعة، استعلام، تحديث مباشر بين نافذتين، إلغاء، إنشاء رحلة، تصدير Excel، طباعة
- ✅ ملف Excel فُتح بـ openpyxl و LibreOffice بنص عربي سليم واتجاه من اليمين لليسار

### مطابقة معايير القبول

| المعيار | كيف تم التحقق |
|---|---|
| مستخدمان من جهازين يحجزان وتظهر الحجوزات لكليهما | اختبار SQL (1) + اختبار نافذتين في المتصفح + Realtime |
| لا يتجاوز الإجمالي 50 مقعدًا | قيد CHECK + قفل الصف + اختبار 150 طلبًا متزامنًا |
| مقعد واحد متبقٍ يرفض حجز مقعدين | اختبار SQL (4) + تزامن (3) + اختبار وحدة |
| إلغاء 3 مقاعد يتيحها مجددًا | اختبار SQL (5) |
| فصل حجوزات الأسابيع | اختبار SQL (6) |
| الزائر لا يصل للإدارة | اختبارات SQL (2، 3): رفض مباشر من قاعدة البيانات |
| الهواتف لا تظهر للزوار | `get_public_bookings` لا تُرجع الهاتف، والجدول مغلق أمام الزوار |
| تصدير Excel | اختبار وحدة + فتح الملف ببرنامجين |
| عربي ومتجاوب | لقطات شاشة هاتف وكمبيوتر |
| البيانات باقية بعد إغلاق المتصفح | التخزين في PostgreSQL (بعد ربط Supabase) |

## 6. ملاحظات

- الحجز بعدد المقاعد وليس باختيار مقعد بعينه؛ مخطط الأتوبيس يوضح نسبة الإشغال بصريًا فقط.
- الحد الأقصى للحجز الواحد (افتراضيًا 10 مقاعد) قابل للتعديل لكل رحلة، ويمنع شخصًا واحدًا من حجز الأتوبيس كله. المسؤول غير مقيد به.
- كل الأوقات تُعرض وتُدخل بتوقيت القاهرة (مع دعم التوقيت الصيفي).
- لتعديل نقاط التجمع أو الوجهة أو أي نص في الرحلة لا حاجة لتعديل الكود.

## 7. التحديثات على قاعدة بيانات قائمة

إذا كانت قاعدة البيانات منشأة من قبل، شغّل ملفات التحديث بالترتيب في Supabase → SQL Editor:

| الملف | ما يضيفه |
|---|---|
| `supabase/update-1-route-notices.sql` | التنبيهات، مسار الرحلة، الخريطة، نقاط التجمع (المستقبل، الشروق)، موعد 7:30 |
| `supabase/update-2-full-names.sql` | إظهار اسم الحاجز كاملًا في قائمة الركاب العامة |
| `supabase/update-3-self-edit.sql` | تعديل/إلغاء الراكب لحجزه بالاسم + الهاتف، منع تكرار الاسم أو الهاتف، الهاتف إجباري |
| `supabase/update-4-receipts.sql` | رفع صورة إيصال إنستاباي من الموقع (بالاسم + الهاتف)، ومراجعتها وتأكيد الدفع من لوحة التحكم |

كل التنبيهات والمسار وروابط الخريطة قابلة للتعديل لاحقًا من لوحة التحكم ← الرحلات ← تعديل.

### آلية الدفع الحالية
بعد الحجز يظهر زر **«أرسل صورة التحويل على واتساب»** يفتح محادثة مع رقم إنستاباي برسالة جاهزة (الاسم، عدد المقاعد، نقطة التجمع، المبلغ)، ويرفق الراكب صورة الإيصال. لا يوجد رقم حجز؛ يتأكد الراكب من حجزه بالبحث عن اسمه في قائمة الركاب.
